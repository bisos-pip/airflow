* Key Design Decisions

  - *Dedicated =airflow= account, not root.* =/etc/default/airflow= is
    =root:airflow= 640: readable by the service account, not writable by it.
  - *Runtime state in =/opt/airflow=; Python in the shared
    =/bisos/venv/py3/asc=*, not a per-app venv.
  - *PostgreSQL, peer auth, no secret anywhere.* SQLite was rejected as
    single-writer and dev/test only.
  - *The backend is set via the environment*
    (=AIRFLOW__DATABASE__SQL_ALCHEMY_CONN=). The package never templates
    =airflow.cfg= and does not choose the executor.
  - *=/etc/default/airflow= is written only when absent*, so hand overrides
    survive. That is the cause of the write-once gap.
  - *A separate =dag-processor= unit*: on Airflow 3, without it every unit is
    green and no DAG registers.
  - *An absolute =cbsSpec= in the CBM leaf*, so PATH order can't redirect
    materialization. Before 2026-10-01, stale =/bisos/asc/web/bin/= copies
    shadowed the package on PATH (archived 4.3). "Make the package win on
    PATH" was not an option, because it was not pip-installed (it is, since 2026-10-03).
  - *sbom pseudo-packages* (=airflowAcctEnvSetup=, =airflowPostgresSetup=) run on
    every =sbom_fullUpdate=: they must stay idempotent, and their order in
    =aptPkgsList= is load-bearing.
  - *Always reference repos via =/bisos/git/bxRepos/...=.* The anon clone of
    =bro_rawBisos= is stale (last pulled 2026-08-26) and once misled an
    investigation. The rule now lives in the =AI-Activity.org= templates.
