* Architecture

  Single-host Airflow 3 as a BISOS Capability Bundle. Everything lives in
  =py3/bin/=; =py3/bisos/airflow/= is an empty package.

  #+begin_example
  CBM leaf  /bisos/platform/sys/cbm/collective/hereWeb/airflow/cbmProc.spcs   (bro_rawBisos repo)
     |  cbsSpec = absolute path
     v
  CBS       airflow-cbs.pcs   (bisos.capability cba_seed + cba_sysd_seed)
     |-- sbom      airflow-sbom.pcs     account, /opt/airflow, /etc/default/airflow,
     |                                  apt+pip into /bisos/venv/py3/asc, PostgreSQL role+db
     |-- units     airflow-{db,webserver,scheduler,triggerer,dag-processor}-sysd.pcs
     |                                  (bisos.debian systemd_seedInfo, User=airflow)
     '-- assemble  airflow-assemble.cs  -> airflow-here-dns.pcs (bisos.dnsCap, /etc/hosts)
                                        -> airflow-wvd.pcs      (bisos.webCap, nginx vhost)
  Operator CSs: airflowAdmin.cs (host/services/users/DAGs info), quickAirflow.cs (CLI cheat sheet)
  #+end_example

  - Port: =bisos.banna= =tcpPortsList['airflow']= (24006 here); FQDN =airflow.here=.
  - Docs: Blee panels under =py3/panels/bisos.airflow/=. The authoritative
    one is =airflowUsage=; the panel subtree has its own =AI-*= overlay
    (=initiateSub=).
  - Not pip-installed on this host. Commands are run by full path under

* Key Design Decisions

  - *Dedicated =airflow= account, not root.* All units run as
    =User=airflow=. =/etc/default/airflow= is =root:airflow= 640: readable
    by the service account, not writable by it.
  - *Runtime state in =/opt/airflow=, Python in the shared
    =/bisos/venv/py3/asc=*, rather than a per-app venv.
  - *PostgreSQL with peer auth, no password anywhere.* The connection
    string carries no user or secret; the OS account maps to the
    like-named role. SQLite was rejected as single-writer and dev/test
    only.
  - *The backend is set through the environment, not =airflow.cfg=*
    (=AIRFLOW__DATABASE__SQL_ALCHEMY_CONN= in =/etc/default/airflow=). The
    package never templates =airflow.cfg=, and *does not choose the
    executor*.
  - *=/etc/default/airflow= is written only when absent*, so hand-added
    overrides survive. The cost is the write-once gap noted above.
  - *A separate =dag-processor= unit*: on Airflow 3, without it every unit
    is green and no DAG is registered.
  - *The CBM leaf uses an absolute =cbsSpec=*, so PATH order cannot
    redirect materialization. Stale PATH copies once did (4.3).
  - *Pseudo-packages in the sbom* (=airflowAcctEnvSetup=,
    =airflowPostgresSetup=) run on every =sbom_fullUpdate= and must stay
    idempotent. Their position in =aptPkgsList= is load-bearing.
