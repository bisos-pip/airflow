This panel is the authoritative description of what =bisos.airflow= provides and
how a deployment made with it is laid out. It is package-level: it describes the
mechanism, not any particular deployed instance. Instance-specific facts
(hostnames, which DAGs, local overrides in =/etc/default/airflow=) belong to the
project that deploys it.

Downstream projects that deploy Airflow the BISOS way =@=-import this file into
their own =AI-Activity.org=. Import it through =/bisos/git/bxRepos/...=:

: @/bisos/git/bxRepos/bisos-pip/airflow/py3/panels/bisos.airflow/airflowUsage/_nodeBase_/fullUsagePanel-en.org

Known gaps and package maturity are tracked in this repo's =AI-DevStatus.org= and
=AI-WorkPlan.org=, not here.

*** Purpose and Scope

=bisos.airflow= (source under =py3/= in
=/bisos/git/bxRepos/bisos-pip/airflow=) installs and runs an Apache Airflow
platform on a single Debian host as a BISOS *Capability Bundle*: an SBOM for
packages and the metadata DB, one systemd unit per Airflow role, and an
assemble step for DNS + nginx exposure. It sits between a single monolithic
=airflow standalone= process and a distributed/HA deployment (Celery,
Kubernetes) --- see the =serverSetup= panel for that positioning.

Covered: account and directory layout, package install (via =bisos.sbom=), the
PostgreSQL metadata DB, systemd units for the five Airflow roles, and nginx-vhost
+ DNS exposure. Not covered: choosing an executor, templating =airflow.cfg=, and
bridging DAG tasks into other Python venvs --- see below.

*** Account, Directories and Environment

Everything runs as the dedicated system account =airflow=, not as root.
=airflow-sbom.pcs= sets this up through the =airflowAcctEnvSetup= pseudo-package,
which runs (idempotently) on every =sbom_fullUpdate=:

| What                        | Where                                  | Notes                                            |
|-----------------------------+----------------------------------------+--------------------------------------------------|
| System user                 | =airflow= (=useradd -r -m=)            | created only when absent                         |
| =AIRFLOW_HOME=              | =/opt/airflow=                         | runtime state only: =dags/=, =logs/=, =airflow.cfg= |
| Python venv                 | =/bisos/venv/py3/asc=                  | shared with other bisos packages, not per-app    |
| Runtime dir                 | =/run/airflow= (=/etc/tmpfiles.d/airflow.conf=) | PID and socket files                     |
| Unit environment            | =/etc/default/airflow=                 | =root:airflow= 640, read via =EnvironmentFile== |

=/etc/default/airflow= is written *only when absent*, so hand-added overrides
survive re-runs. As written by the package it contains:

- =AIRFLOW_HOME=/opt/airflow=
- =AIRFLOW__DATABASE__SQL_ALCHEMY_CONN=postgresql+psycopg2://@/airflow?host=/var/run/postgresql=
- =AIRFLOW__API__BASE_URL=http://<fqdn>= --- the address humans browse, through nginx
- =AIRFLOW__CORE__EXECUTION_API_SERVER_URL=http://localhost:<port>/execution/=

The last one is not optional. Airflow 3 task processes reach the api-server over
HTTP (the Task Execution API). When it is unset the task SDK falls back to
=http://localhost:8080=; because the port here comes from =bisos.banna=, every
task then dies with =[Errno 111] Connection refused= while all units stay green.
A host whose =/etc/default/airflow= predates these lines must get them by hand ---
either there, or as =[core] execution_api_server_url= / =[api] base_url= in
=airflow.cfg=.

Run Airflow CLI commands the way the units do: as =airflow=, with that
environment, e.g. =sudo -u airflow env $(sudo cat /etc/default/airflow | grep -v '^#') /bisos/venv/py3/asc/bin/airflow dags list=.

*One source for these facts.* The account, =AIRFLOW_HOME=, the environment file, the venv,
the fqdn, the port, the metadata DB connection string and the version floor are defined
once, in =bisos.airflow.airflowInfo= (=py3/bisos/airflow/airflowInfo.py=). The sbom, all
five units, =airflow-here-dns.pcs=, =airflow-wvd.pcs=, =airflowAdmin.cs= and =quickAirflow.cs=
read it, so they cannot disagree. The module is pure --- no side effects --- and also holds
the generators for the text of =/etc/default/airflow= and of the units' =User=/=Group=/
=EnvironmentFile= lines, and the functions that compare them with a live host.
=airflowAdmin.cs -i driftCheck= runs that comparison, read-only. A live file that lacks a
generated line is reported, not fixed: the file stays write-once.

*** Packages and the Metadata DB

=airflow-sbom.pcs= (a =bisos.sbom= planted file) installs:

- apt: =python3=, =python3-pip=, =python3-venv=, =build-essential=, =libpq-dev=,
  =libssl-dev=, =libffi-dev=, =pkg-config=, =postgresql=.
- pip, into =/bisos/venv/py3/asc=: =apache-airflow= (=>=3.0=: the units need =api-server=,
  =dag-processor= and the Task Execution API, which only Airflow 3 has), =psycopg2= (sync driver) and
  =asyncpg= (async driver --- Airflow 3 builds an async engine too; without it
  every CLI call and unit fails with =ModuleNotFoundError: asyncpg=).

The metadata DB is *PostgreSQL*, provisioned by the =airflowPostgresSetup=
pseudo-package: a =LOGIN= role and a database, both named =airflow=, and
=max_connections= raised to 200 (five units each hold a SQLAlchemy pool). Auth is
*peer auth over the unix socket*: the connection string carries no user and no
password, and PostgreSQL maps the =airflow= OS account to the like-named role. No
secret appears in =/etc/default/airflow= or =airflow.cfg=. SQLite (Airflow's
default) is not used: it is single-writer and documented as dev/test only.

The web UI uses Airflow 3's simple auth manager. The admin password is
auto-generated into =/opt/airflow/simple_auth_manager_passwords.json.generated=
(airflow-owned); =airflow-sbom.pcs -i adminPasswd= prints it.

*** The Five systemd Units

Each role is a planted =*-sysd.pcs= in =py3/bin/= calling
=bisos.debian.systemd_seedInfo.setup(seedType="sysdSysUnit", ...)=. The =airflow=
executable path is resolved at materialization time with
=pathPlus.whichBinPath("airflow")=. All five units have =User=airflow=,
=Group=airflow= and =EnvironmentFile=/etc/default/airflow=.

| Unit (=.pcs=)                       | Role                         | =ExecStart= sub-command          | Type / ordering                                              |
|-------------------------------------+------------------------------+----------------------------------+--------------------------------------------------------------|
| =airflow-db= (=airflow-db-sysd.pcs=) | metadata schema migration    | =airflow db migrate=             | =oneshot=, =RemainAfterExit=yes=; =Requires=/=After=postgresql.service= |
| =airflow-webserver=                 | API server + web UI          | =airflow api-server --port <port>= | =Requires=/=After=airflow-db.service=                       |
| =airflow-scheduler=                 | scheduler                    | =airflow scheduler=              | =Requires=/=After=airflow-db.service=                        |
| =airflow-triggerer=                 | triggerer (deferrable tasks) | =airflow triggerer=              | =Requires=/=After=airflow-db.service=                        |
| =airflow-dag-processor=             | DAG file parsing             | =airflow dag-processor=          | =Requires=/=After=airflow-db.service=                        |

=airflow-dag-processor= is required on Airflow 3, which parses DAG files in a
standalone process rather than in the scheduler. Without it every unit is
healthy and no DAG is ever registered.

=api-server= is the Airflow 3 sub-command name (Airflow 2 used =webserver=); the
unit name =airflow-webserver= is historical. The port is looked up by name from
the =bisos.banna= registry (=tcpPortsList['airflow']=); =bisos.airflow= performs
the lookup but does not own the port assignment.

*** Capability Bundle: CBS and CBM

- *CBS* --- =py3/bin/airflow-cbs.pcs= declares the bundle: =sbom="airflow-sbom.pcs"=,
  =assemble="airflow-assemble.cs"=, and the five units above as
  =sysdUnitsListAirflow=. Materializing it runs the sbom, then the assemble step,
  then ensures each unit.
- *CBM* --- the planted leaf
  =/bisos/platform/sys/cbm/collective/hereWeb/airflow/cbmProc.spcs= (in the
  =bro_rawBisos= repo) is a pointer: =capabilityName="airflow"= and
  =cbsSpec="/bisos/git/bxRepos/bisos-pip/airflow/py3/bin/airflow-cbs.pcs"= ---
  an absolute path, so PATH order cannot redirect it. Its sibling
  =cbmProc.control= gates materialization; =cbmProc.status= logs each run.
  The package also ships the same pointer as =py3/bin/cbmProc-airflow.spcs=.

See the =cbm-authorship= and =sysd-pcs-authorship= skills for the mechanics.

*** Exposure: nginx vhost + DNS

=airflow-assemble.cs -i fullUpdate= runs two steps:

- =hereDns()= runs =airflow-here-dns.pcs -i dnsCap_update= --- wraps
  =bisos.dnsCap=, resolving the FQDN (=airflow.here=) via =/etc/hosts=
  (=DnsSpecMethod.etcHosts=), not real DNS.
- =webVirtDom()= runs =airflow-wvd.pcs -i configFileUpdate --cls="configFile_nginxVd" --runAs=root=
  then =-i webVd_enable= --- wraps =bisos.webCap=, building an nginx vhost with
  =webVd_nginxSites.atPortSite(serverName=, proxyIp=, proxyPort=)=, proxying to
  the banna-assigned port.

Re-run =airflow-assemble.cs -i fullUpdate= (or the two =.pcs= commands) to change
vhost/DNS config; hand-editing the generated nginx config or hosts entry defeats
reproducibility.

*** Executor: Not This Package's Decision

The package chooses the *backend* (PostgreSQL, via
=AIRFLOW__DATABASE__SQL_ALCHEMY_CONN=, which overrides =airflow.cfg=) but not the
*executor*. Nothing in =bisos.airflow= sets =core.executor= or templates
=airflow.cfg=, so the executor is whatever the instance's =airflow.cfg= (or an
=AIRFLOW__CORE__EXECUTOR= line added to =/etc/default/airflow=) says. Check the
instance; don't infer it from this package. (The =serverSetup= and
=scalingExecutors= panels assume =LocalExecutor=.)

*** Cross-Venv DAG Code: Not This Package's Concern

=bisos.airflow= has no opinion on how a DAG task reaches code installed in a
Python venv other than Airflow's own (=/bisos/venv/py3/asc=). There is no
=PythonVirtualenvOperator= template and no subprocess/wrapper convention in its
source. Bridging (subprocess into the other venv's interpreter, a
=BashOperator=, a =PythonVirtualenvOperator=, ...) is up to whoever writes the
DAG and is documented per deployment.

*** Commands

| Command                              | Purpose                                                           |
|--------------------------------------+-------------------------------------------------------------------|
| =airflow-sbom.pcs -i sbom_fullUpdate= | install account, packages and metadata DB                        |
| =airflow-sbom.pcs -i readme=          | describe what the sbom installs                                  |
| =airflow-sbom.pcs -i adminPasswd=     | print the auto-generated admin password (reads =/opt/airflow= as root) |
| =airflow-cbs.pcs -i cbs_materialize=  | sbom + assemble + ensure all units                               |
| =airflow-<role>-sysd.pcs -i sysdSysUnit status= | per-unit status (also =ensure=)                        |
| =airflowAdmin.cs=                     | host/services/users/DAGs info (starting point, not complete)     |
| =airflowAdmin.cs -i driftCheck=       | read-only: live env file and units against =airflowInfo=         |
| =quickAirflow.cs=                     | quick-reference menu of Airflow CLI commands (starting point)    |

The =.pcs= files import =bisos.airflow=, so the package must be installed. On this host it is
an editable install into =/bisos/venv/py3/bisos3=, made with
=pypiProc.sh -i pkgReInstall edit /bisos/venv/py3/bisos3=. That also symlinks the commands
into =/bisos/venv/py3/devbin/=, which puts them on PATH, so a bare name such as
=airflow-cbs.pcs= resolves to the package source. The install also leaves *copies* of the
scripts in =/bisos/venv/py3/bisos3/bin/=; they go stale as =py3/bin/= changes, so run
=pkgReInstall= again after changing a script. Without an install, invoke the commands by
full path under =/bisos/git/bxRepos/bisos-pip/airflow/py3/bin/=, which also needs
=bisos.airflow= importable.
